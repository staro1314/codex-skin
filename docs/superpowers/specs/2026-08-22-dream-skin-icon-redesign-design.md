# Codex Dream Skin 应用图标重新设计：轻纱·霜白

## 状态

待用户审核设计规格。当前阶段不修改现有图标源码、生成资产、版本号或发布配置。

## 背景与目标

当前图标使用“白色圆角方、墨色对角面、青色圆点”的旧标记，并在 macOS Swift 生成器、Windows PowerShell 生成器和 SVG 中分别维护几何规则。用户希望完全重新设计，气质确定为“梦幻克制”，最终选定“轻纱”符号和“霜白”色彩处理。

本次设计的目标是：

- 用一个可独立识别的符号表达主题覆盖、透明层和轻微梦境感。
- 在 16px 托盘图标中仍能看出轮廓，不依赖文字、渐变细节或复杂装饰。
- 让 macOS ICNS、Windows ICO、系统托盘、安装器和快捷方式使用同一套品牌语义。
- 保持现有启动、注入、安装、升级、卸载和主题功能不变。

## 已确认的设计决定

### 核心符号：轻纱环带

- 外层仍使用平台友好的圆角方形底板，但不再使用对角切分。
- 中心符号是一条连续、未闭合的柔和环带，形成一个留白窗口。
- 环带的开口是“呼吸口”，用于表达轻纱被轻轻掀起，而不是形成封闭的字母或徽章。
- 环带使用一条主笔画加一条低透明度的软底笔画，主笔画保持清晰，软底只提供轻微层次。
- 左上区域保留一个小的紫色微光点，作为远距离识别锚点；不增加星星、文字、阴影图案或其他装饰。

### 色彩：霜白

颜色必须低饱和、偏暖白，并在浅色和深色系统背景上都保持可见：

| 角色 | 目标颜色 | 用途 |
|---|---|---|
| Frost base | `#F0EEF3` → `#CBD7D7` | 圆角底板的克制冷暖过渡 |
| Veil highlight | `#FFFDF7` | 环带高光和留白边缘 |
| Veil lilac | `#DBD6E9` | 环带中段的淡紫过渡 |
| Veil mint | `#B3D8D4` | 环带末段的极弱薄荷过渡 |
| Veil underlay | `#8E87B2` at 22% | 环带背后的柔和层次 |
| Quiet point | `#8980B8` | 单一微光点 |
| Fine outline | `#252731` at 12% | 底板发丝级边缘，避免浅色背景上消失 |

约束：只允许一条线性三色过渡，不使用径向光晕、发光滤镜、噪点、玻璃纹理或外部阴影。实际落地时可以在非常大的 macOS 图标尺寸上保留极弱抗锯齿，但不得引入尺寸相关的不同构图。

### 几何与尺寸

- 设计基准为 `32 × 32` viewBox；底板为 `x=2, y=2, width=28, height=28, rx=9`。
- 主环带采用圆角线帽和圆角连接，主笔画约为底板尺寸的 37.5%；软底笔画约为主笔画的 2 倍。
- 开口在小尺寸下至少保留约 2px 的可见间隙，避免缩小后变成封闭圆环。
- 微光点在 32px 预览中直径约 4px，在 16px 预览中仍至少保留约 2px 的实心面积。
- 不放置任何字母、产品名称、官方 Codex/OpenAI 标志或平台专属文字。
- 1024px macOS 源图和 Windows 超采样计算必须遵循同一比例、同一开口位置和同一颜色角色，不允许平台各自重新构图。

## 实现边界

### 共享品牌源

`docs/images/dreamskin-mark.svg` 作为可审阅的 32px 语义源，更新为“轻纱·霜白”。它只表达品牌图形，不承载运行时 CSS、网页布局或客户端行为。

### macOS

保留 `macos/scripts/generate-app-icon.sh` 的输出流程和 `macos/menubar-app/Tools/generate-icon.swift` 的原生 PNG/ICNS 生成职责，只替换绘制几何和颜色常量。继续生成完整的 `iconset` 尺寸集合，不改变菜单栏应用的 bundle、签名、安装或启动逻辑。

### Windows

保留 `windows/installer/build-release.ps1` 的多尺寸 ICO 结构以及现有托盘、安装器和快捷方式路径，只替换 `Write-DreamSkinIcon` 的几何采样和颜色混合规则。继续保留 16、24、32、48、64、256 尺寸，不改变 ICO 容器格式、安装流程或托盘行为。

### 不在本次范围

- 不修改 Codex 官方安装包、`app.asar`、签名或系统权限。
- 不改变应用窗口、主题渲染、CDP 注入、主题 ZIP、自动更新或 Release 版本。
- 不删除旧图标历史记录；只更新当前品牌源和构建时生成规则。
- 不把设计稿 PNG 直接作为唯一生产资产；生产图标仍由两端现有生成器构建。

## 验收标准

### 视觉

- 16px、20px、24px、32px、128px、256px 预览中都能辨认“未闭合环带 + 留白窗口 + 单一微光点”。
- 浅色、深色桌面上底板边界和主环带均清楚，但不产生高亮刺眼的发光效果。
- macOS 和 Windows 输出在构图、开口位置、颜色角色和视觉重量上保持一致。
- 图标不包含文字、旧对角切分、旧青色圆点或任何官方 Codex/OpenAI 标识。

### 工程与功能

- SVG 合同测试验证 viewBox、非空几何、无文本、关键颜色角色和开口存在。
- Windows 生成器测试验证 ICO 目录仍包含六个目标尺寸、每个图像非空且 alpha 有效。
- macOS 生成器脚本和 Swift 源通过适用的语法/静态检查；在 macOS 环境生成 ICNS 后验证非空和尺寸集合。
- `node --test windows/tests/*.test.mjs tools/*.test.mjs`、Windows 安装器静态测试及适用的 macOS 测试通过。
- `git diff --check` 通过，且工作区不产生未跟踪的生产图标副本。
- 应用启动、托盘菜单、安装器快捷方式、主题应用和恢复流程的行为回归不受影响。

## 实施顺序（设计确认后）

1. 更新 SVG 语义源和两端绘制常量；先补充失败的图标合同断言。
2. 实现 macOS/Windows 图标生成规则，并验证生成的多尺寸输出。
3. 运行双端静态与回归测试，检查 `git diff --check`。
4. 在浅色/深色桌面和托盘尺寸下做人工视觉复核；确认安装器引用仍指向现有路径。
5. 汇总变更和验证结果，再由用户决定是否进入版本/Release 流程。
